Replacing Qt libraries on Windows x64:
1. Close all vividcode processes. Back up the installation's runtime directory.
2. Use the matching Qt sources, a compatible MSVC 2022 x64 toolchain and CMake.
   In an x64 developer shell, configure a SHARED release build, e.g.:
     mkdir qtbase-build
     cd qtbase-build
     ..\qtbase-everywhere-src-6.11.2\configure.bat -prefix C:\QtCustom -release -shared -opensource -confirm-license -nomake examples -nomake tests -qt-zlib
     cmake --build . --parallel
     cmake --install .
   Configure qtsvg in a separate build directory with the installed base:
     cd ..
     mkdir qtsvg-build
     cd qtsvg-build
     C:\QtCustom\bin\qt-configure-module.bat ..\qtsvg-everywhere-src-6.11.2
     cmake --build . --parallel
     cmake --install .
   Keep SQLite, Windows platform, Schannel TLS and SVG support enabled. Consult
   the preserved upstream summaries for ABI/features. Adapt paths to your machine.
3. Replace runtime/Qt6*.dll with compatible release x64 builds and update their
   matching plugins (platforms, sqldrivers, tls, imageformats, iconengines, styles,
   networkinformation). Do not mix debug/release or incompatible architectures.
4. Start runtime/vividcode-viewer.exe or an existing project launcher. No library
   signature/key check prevents running user-modified Qt libraries. The installer
   checks copy integrity only during installation; it does not lock installed DLLs.
5. If an ABI change needs an application rebuild, the complete MIT application
   source, CMakeLists.txt and build.ps1 are available at the same 0.1.0 tag. Use
   build.ps1 -QtRoot C:\QtCustom or set CMAKE_PREFIX_PATH to your Qt installation.
   Back up custom libraries before upgrades; upgrades replace runtime files.
