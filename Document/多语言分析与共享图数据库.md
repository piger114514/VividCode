# 多语言分析与共享图数据库

更新日期：2026-10-02。

## 当前行为

用户确认按语言分组分别分析，结果进入同一套数据库与图形界面；混合项目在同一画布同时显示各语言结果并分区排列。已接入的语义分析语言为 C++ 和 C#；Python、JavaScript/TypeScript、Java 当前仍仅支持源码文件浏览。

打开项目时自动检测各语言工程，无语言选择框。C# 只查项目目录第一层 `.sln`，一个直接分析、多个在列表中单击选择；没有解决方案时检查根目录 `.csproj` 或以前导入的工程。C++ 使用以前导入的有效编译数据库，或根目录 / `build/` 中的 `compile_commands.json`。缺配置时右键“导入工程配置…”。不根据扩展名猜测编译参数，也不执行编译数据库中的编译命令。

多入口选择发生在对应语言内部，不要求在 C# 与 C++ 之间二选一。同项目刷新记住入口；右键“重新选择分析工程…”清除本次选择。当前每种语言选一个分析入口，入口包含的项目引用、解决方案项目或编译单元交给该语言后端处理。多个独立解决方案同时分析尚未实现。

各后端独立运行，但按语言顺序执行，复用已有语义操作锁。打开时先显示缓存，再后台检查；F5 或右键“刷新文件和索引”重新扫描及索引。C# Debug/Release 和目标框架在顶部，改配置会自动刷新。没有后台文件监控。

## 共享数据与边界

`%LOCALAPPDATA%/vividcode/semantic/<项目路径哈希>/graph.db` 是同一个项目的共享展示数据库，Qt 使用 QSQLITE 读取。schema 1：

- `language_states(language, state)` 保存每种语言最近成功的状态 JSON。
- `graph_units(language, unit_key, payload)` 保存统一导出格式的工程/编译单元 JSON，包括符号和关系。

这一步统一结果持久化和展示接口。数据库目前保存 JSON 快照，尚未把每个符号与关系拆成可直接做复杂 SQL 图查询的独立表。C++ 的 `index.db` 和 C# 的 `csharp/index.json` 继续作为各自的增量分析缓存，避免重写已有依赖指纹与故障恢复机制。

成功结果按语言在单事务中替换，失败不覆盖该语言上次成功的共享快照，也不删除其它语言结果。展示状态仍取后端最新配置，因此失败时会标出 failed 并保留旧图。缓存目录和数据库检查链接与项目归属；未知数据库版本拒绝覆盖。`-d` 清除包括 graph.db 在内的本项目集中缓存；`-c` 保留语义缓存。

展示层为符号 ID、parent_id 和关系端点增加语言前缀，防止不同语言碰撞；不根据同名符号制造跨语言调用线。C++ 全范围是当前导出的各 TU/配置关系的并集，未实现不同宏配置之间的语义一致性判断；需要查看具体配置时可使用分析范围下拉框。C# 仍只分析当前加载的配置与目标框架。

## 界面与源码速览

左侧“项目文件”和“结构与关系”是同一个位置的两个页签；结构树按语言列出类/方法/成员，下方列出关系。已移除“选择符号”下拉行。单击选中，结构树或图中双击可查看相关关系；“显示全部工程关系”回到全范围。

顶部原按钮行的位置改为关系类型、Debug/Release、目标框架。旧打开项目/刷新/缩放按钮、手动语言选择、更新/取消按钮和底部嵌入源码栏已移除。Ctrl+O、F5、滚轮缩放保留，右键菜单提供刷新、工程导入、重选和取消；画布额外提供适应画布。

节点、类容器、连线、结构/关系列表和文件树右键“查看源代码”打开只读小窗口，只有代码及右上角 ×。多处关系在菜单中列出发生位置。单击不自动弹源码。点击窗外、切换其它应用或按 Esc 关闭并清空内容；项目切换/刷新也关闭。打开延后到右键菜单关闭后，避免菜单生命周期干扰。源码限定项目内，UTF-8，2 MiB 上限；暂无语法高亮和行号栏。

语言分区共用一个 scene，初始概览适配可视区域，各语言独立应用类/成员缩放与节点上限：每种语言最多 81 节点 / 160 条合并线；完整关系仍在列表。布局不持久化，拖动可能改变分区视觉边界。跨语言 FFI/PInvoke 等关系尚未提取，图中仅显示后端已有证据。
