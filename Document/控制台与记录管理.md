## 当前需求与行为

用户已确定：项目目录不放 analyzer、semantic 或 Qt DLL；本机当前用户安装一份共享程序和分析环境，项目只保存启动 exe 与 JSON 历史。共享位置为 `%LOCALAPPDATA%\vividcode`。本轮是现有 C++/Qt 工程的增量修改，没有重写解析器或图谱。

| 命令 | 当前行为 |
| --- | --- |
| `vividcode -g` | 在当前目录创建/更新 `.vividcode` 启动器与 JSON 历史；迁移旧项目内索引，清除旧运行附件 |

## 安装与运行

2026-10-02 已核实：本机 Codex 工具进程（包含沙箱外执行）会将 AppData/Local/vividcode 重定向到 Codex 应用包的 LocalCache。因此此前工具安装和 PATH 检查通过不证明用户独立终端可用。应在从开始菜单打开的独立 PowerShell 中执行安装脚本；用户侧恢复尚待验收，安装脚本尚未检测重定向。物理文件句柄证据见[构建环境与运行](构建环境与运行.md)。

在源码 `VividCode/` 中先构建 Release，然后运行：

```powershell
.\install-command.ps1
```

该脚本调用 `install-runtime.ps1`，从 `build/Release` 安装共享运行包，并把 `%LOCALAPPDATA%\vividcode\runtime` 注册到当前用户 PATH。移除本工程旧 build/Release、x64/Release 及同根 CUGB_Graph/build/Release 的 PATH 项，不修改其它项目路径或系统 PATH。旧终端、IDE 需重开。可通过 `-RuntimeDirectory` 选择原始 VS 的 x64/Release 产物。

在真实项目根目录执行 `vividcode -g`，双击 `.vividcode/vividcode-viewer.exe`。该 exe 是原生 Windows 小启动器，不依赖项目旁的 Qt/Python DLL；根据自身路径确定项目根目录，再以 `--project` 参数调用共享 Qt 查看器。它从任意工作目录启动都能定位项目，等待查看器结束并传递退出码；Job Object 在启动器异常退出时终止其子进程，避免遗留查看器占用锁。

`-g` 不安装或反复更新共享运行包；未安装/不完整时明确报错。升级共享程序重新运行安装脚本，所有项目启动器随后调用新版。项目移动后启动器仍定位自身上级，但语义缓存以当前规范路径区分，需要重新导入有效编译数据库。另一台电脑或另一个 Windows 用户需安装共享程序，项目 exe 不再是完整便携运行包。

## 目录结构

```text
目标项目/
  .vividcode/
    vividcode-viewer.exe       # 无 Qt 依赖的小启动器
    project.json
    records/
      record-<UUID>/
        index.json

%LOCALAPPDATA%/vividcode/
  runtime.lock                # 共享程序安装/运行互斥
  runtime/
    vividcode.exe
    vividcode-viewer.exe       # 真实 Qt 查看器
    vividcode-launcher.exe
    installation.json
    [Qt DLL 与插件]
    analyzer/                 # 一份 Python/libclang 与内置头文件
  semantic/
    <项目规范路径的 SHA-256>/
      project.json            # 此缓存的项目归属
      config.json
      index.db
```

正常新生成的项目输出只有 exe 与 JSON；不再生成 README.md 或 code.md。项目根目录的 `.vividcode.lock`、`.vividcode-semantic.lock` 和 `.vividcode-viewer.lock` 是操作/进程期间的临时锁，正常退出释放。

项目 `project.json` 仍为 app=vividcode、schema=1，包含 projectRoot=".."、latest、history；新增 deployment="shared"、cacheKey 作为部署和缓存标识。删除路径由规范项目路径重新计算，不信任 manifest 中的任意路径。记录 JSON 保存相对源码路径、字节数、内容 SHA-256、UTC 创建时间及整份记录的 fingerprint；不保存源码副本。

## 记录保存与清理

首次 `-g` 保存一份完整文件级记录。以后执行 `-g`，或查看器打开已初始化项目/F5 刷新，比较文件内容哈希；新增、修改、重命名或删除时创建新记录，内容不变则复用 latest。先原子写 index.json，再原子更新 project.json；崩溃遗留未登记记录不作为最新。

支持的源码扩展名、排除规则和数量上限复用 ProjectScanner。达到上限或读取失败时不提交不完整快照。`-c` 校验最新 JSON 和 manifest，再按登记的 history 清理；不依据文件时间挑最新，不删除未知文件、源码或人工 Document 文档。记录仍不包含编译配置变化，编译配置与语义更新由独立分析器管理。

## 从旧版迁移

新版 `-g` 对已经有有效 manifest 的项目：

1. 校验已登记记录的 JSON；原有 index.json 字节和记录 ID 保留。
2. 将旧 `.vividcode/semantic` 的配置/SQLite 文件复制到此项目的集中缓存，逐文件核对 SHA-256，全部一致后删除旧语义目录。
3. 共享缓存已有不同内容时拒绝覆盖，保留两份数据并报错；复制或校验失败保留旧数据，允许重试。
4. 用小启动器替换旧查看器；清除旧 Qt DLL、已知插件、analyzer、demo 和生成的 Markdown 概览。未知人工文件不主动删除。

迁移允许 config.json、index.db 和 SQLite journal/WAL/SHM 附件，遇到未知内容拒绝迁移。文件级历史 JSON 不因概览 Markdown 移除而丢失。整个升级仍不是跨文件事务；出现失败按提示修复后重新 `-g`，不要先 `-d` 删除历史。

## 锁、路径和失败边界

- 项目操作仍使用 QLockFile 与 Windows 独占语义句柄；分析/导出与 -g/-d 不能并发，活动查看器阻止项目生成/删除。
- 项目生成目录和当前项目集中缓存删除前检查整棵树，拒绝符号链接、junction 和 reparse point；共享路径额外检查祖先目录。
- 集中缓存按规范项目路径转成统一斜线、小写 UTF-8 后 SHA-256 分目录，C++ 和 Python 使用同一规则。缓存 project.json 必须声明 app/schema 及匹配的项目根路径，否则拒绝修改或删除。
- 共享安装通过 runtime.lock 请求独占访问；查看器、启动器和已安装 CLI 持有读句柄，多项目查看器可并存，但运行期间安装更新被拒绝。安装先校验来源，复制到 staging 并逐文件核对摘要，再交换 runtime；交换失败恢复旧目录，不改 semantic。
- -d 只清除当前项目的缓存分目录，即使项目 .vividcode 已被手动删除也能清除对应缓存；共享 runtime 和相邻项目缓存保留。
- 项目移动/删除后旧路径缓存暂不自动回收，也没有缓存管理界面；共享目录权限不足、文件占用或磁盘不足会报错，可能已完成部分迁移/清理。无回收站或撤销功能。

开发与测试可用绝对路径环境变量 `VIVIDCODE_HOME` 替换共享根目录；产品默认不设置它。测试只操作独立 UUID 临时目录，不污染用户安装或真实项目。
