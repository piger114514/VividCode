# vividcode 控制台与记录管理

更新日期：2026-09-26。

## 用户已确定需求

2026-09-27 更新：`--g` 现在同时预检和复制 `analyzer/` 独立 Python/libclang 运行包。语义缓存存于 `.vividcode/semantic/`，随 `--d` 整体删除，`--c` 保留。ProjectStore 与分析进程使用额外的 Windows 独占生命周期锁，分析过程中拒绝生成/删除。语义使用方式和数据格式见 [C++ 语义索引](C++语义索引.md)。本轮 CLI 生命周期回归通过；下文文件级 records 格式仍保持原样。

正式产品名为 `vividcode`：

| 命令 | 当前行为 |
| --- | --- |
| `vividcode --g` | 在当前工作目录生成或更新 `.vividcode`，部署图形查看器和 Qt 运行依赖，生成代码文件文档记录 |
| `vividcode --d` | 删除当前工作目录中的整个 `.vividcode`；目录不存在时成功返回 |
| `vividcode --c` | 清除已登记的旧记录，仅保留最新成功提交的一份，保留查看器和运行依赖 |
| `vividcode --help` | 显示用法；不带参数也显示帮助 |

一次仅允许一个命令。退出码：成功 0；操作失败 1；参数错误 2。路径始终是当前工作目录，不向父目录搜索，也不处理邻居项目。

## 使用方式

本机已经运行 `../VividCode/install-command.ps1`，将 `../VividCode/build/Release` 的绝对路径注册到当前用户 PATH。重新打开终端即可使用；若终端由长期运行的 VS/IDE 启动，可能需要重启该应用。工作区移动后应重新注册路径。install-command.ps1 会移除同一项目根目录下旧 CUGB_Graph/build/Release 的 PATH 项，再登记 VividCode/build/Release；不移除其它项目的路径。

在目标项目根目录执行：

```powershell
vividcode --g
```

完成后双击 `.vividcode/vividcode-viewer.exe`。它根据自身所在的 `.vividcode` 定位上一级项目，因此可以从其他工作目录启动，也支持整个项目一起移动。程序不会在 `--g` 后自动弹窗。

`--d` 会同时删除运行文件和全部生成记录，执行前应关闭该项目的查看器。`--c` 不会删除当前源码、人工维护的 `Document/` 或运行文件。全部源码存储在原项目中，记录不是源码备份。

用户已再次明确：`--g` 与 `--d` 是创建/删除的一对操作；若后续将分析索引纳入生成流程，`--d` 也应清理该索引，而非为它另留目录。

## 输出目录及记录格式

```text
项目/
  .vividcode/
    vividcode-viewer.exe
    Qt6Core.dll / Qt6Gui.dll / Qt6Widgets.dll / 其他运行 DLL
    platforms/ 等 Qt 插件目录
    demo/
    README.md
    project.json
    records/
      record-<UUID>/
        index.json
        code.md
```

`project.json`：`app: "vividcode"`、`schema: 1`、`projectRoot: ".."`、`latest` 记录 ID 和按提交顺序登记的 `history` 数组。

`index.json`：app、schema、id、createdUtc、fingerprint，以及 files 数组。每个文件保存项目相对路径、字节数和 SHA-256。`code.md` 是对应的 Markdown 文件概览，明确标注没有解析类、函数或调用关系。

最新记录由 `project.json.latest` 指定，不按文件修改时间判断。记录先写入新 UUID 目录，两个文件都成功后再用 QSaveFile 原子提交 manifest。若写入中断，未提交目录不会成为最新记录，也不自动纳入清理范围。

## 何时创建记录

1. 执行 `--g`：先验证运行包，初始化或读取 manifest，更新程序文件，再扫描项目并生成文档。
2. 打开已存在 `.vividcode` 的项目或按 F5 刷新：查看器调用相同存储逻辑，检查并记录代码变化。
3. 文件清单与内容哈希和最新记录相同：复用最新记录，不重复增加历史。新增、删除、重命名或内容变化都会产生新记录；仅修改文件时间不产生新记录。
4. 未初始化项目仍可使用查看器浏览，不会自动生成 `.vividcode`。

扫描采用 ProjectScanner 的扩展名和排除规则，`.vividcode` 必须排除，避免把部署的 demo 文件再次记录。达到扫描上限时拒绝保存不完整快照；读取文件失败时保留原来的最新指针。

## 删除、清理与错误处理

- 以规范化项目路径加固定 `.vividcode` 子目录构成目标，操作前检查整个生成目录，拒绝符号链接和 Windows reparse point（包括 junction）。不将 manifest 中的任意路径当作删除目标。
- 所有记录 ID 校验为 `record-<UUID>`，history 不允许重复 ID，latest 必须属于 history。清理前先确认最新 index.json 和 code.md 可用。
- `--c` 只删除 history 登记的旧记录目录；用户额外放入的未知文件、未提交记录不在自动历史清理范围。目录损坏时返回错误，避免误认“最新”。
- `--g` 遇到没有有效 project.json 的已存在 `.vividcode` 会拒绝覆盖；`--d` 按用户命令删除该固定目录，不要求 manifest 完整。
- `.vividcode.lock` 位于项目根目录，仅用于短时操作互斥；进程正常结束会释放并移除锁。
- 生成的查看器运行期间持有根目录 `.vividcode-viewer.lock`，阻止 --g 更新运行文件和 --d 删除。--c 与记录保存使用同一短时锁，可在查看器空闲时执行。
- Windows 文件被外部进程占用、权限不足等情况下删除可能部分完成，命令会返回失败并提示重试；没有回收站或撤销功能。
- 原子提交应用于单个文档/manifest 文件，整个 Qt 运行包的更新不是一次整体事务。生成失败应按错误提示修复后重新 --g。

## 源码与构建入口

源码在 `../VividCode/`：

| 文件 | 关键职责 |
| --- | --- |
| `cli_main.cpp` | QCoreApplication 控制台入口、参数数量校验、当前工作目录、帮助与退出码 |
| `ProjectStore.h/.cpp` | generate、removeGenerated、cleanHistory、recordIfInitialized；路径检查、文件锁、Qt 部署、哈希记录、原子写入 |
| `main.cpp` | GUI 入口；生成的查看器自动定位项目，持有运行锁；内部 --verify-startup 支持部署启动测试 |
| `VividCode.cpp` | 窗口品牌 vividcode；openProject 扫描后调用 recordIfInitialized，并显示存储结果/错误 |
| `ProjectScanner.h` | 排除 .vividcode，避免自扫描 |
| `CMakeLists.txt` | vividcode CLI、vividcode-viewer GUI、共享静态库 vividcode_store 和两组 CTest |
| `build.ps1` | 编译、部署 Qt 依赖、运行测试 |
| `install-command.ps1` | 将 Release 目录注册到当前用户 PATH，不修改系统级 PATH |
| `tests/cli.Tests.ps1` | 临时目录中测试完整命令生命周期及边界 |
